# Kiim — AI-стилист, который показывает тебя

> Бриф проекта для Claude Code. Лежит в корне репозитория.
> Читай его целиком перед любой задачей.

## 1. Зачем этот проект

Мы — две разработчицы. Проект делаем для заявки на **Higgsfield Soul Camp**
(творческий конкурс для девушек, трек **Tech**). Отбор проходит до кэмпа,
проверяющие смотрят ссылку 30–60 секунд и оценивают **идею, вкус (taste) и
исполнение**. Higgsfield обязательно должен быть частью продукта.

Цель — **не большой продукт, а маленькая, но безупречно сделанная
демонстрация**:
- идея понятна за 5 секунд;
- выглядит как продукт премиальной студии: тёмный, личный, со вкусом;
- реально работает на Higgsfield API (Soul V2 + Soul ID);
- есть живая ссылка, красивый README и gif.

**Качество важнее количества функций.** Если приходится выбирать — режь
функцию, а не полировку. Срок: ~1 день работы + полдня полировки.

## 2. Идея продукта

Higgsfield умеет «нарисовать меня» (Soul ID), но это инструмент для креаторов:
нужно уметь писать промпты. **Kiim** (от каз. «киім» — одежда) — продукт для
обычной девушки с проблемой «что надеть?». Она не пишет промптов: говорит,
**куда идёт**, а стилист подбирает 3 образа и **показывает их на ней самой**
в её личной «аватар-студии».

Питч:
> Your stylist, *wearing* you. Tell Kiim where you're going — and see yourself
> in three looks.

## 3. Два экрана

Продукт = **лендинг** + **студия аватара**. Оба в одном визуальном языке
(см. раздел 7), но с разной ролью.

### 3.1 Лендинг `/` — стиль «премиальная студия» (референс: Aesthetic Labs)
- Hero: слева большой заголовок из двух шрифтов
  («Your stylist, *wearing* you»), подзаголовок в 1 строку, две кнопки:
  оранжевая «Open the studio →» и прозрачная «How it works».
- Справа — лучшее сгенерированное фото авторки в образе, за ним мягкое
  оранжевое свечение. Поверх фото 2 стеклянные карточки:
  «03 looks / per occasion» и «Soul ID / powered by Higgsfield».
- Фон: тонкая сетка и 2–3 едва заметные искры ✦.
- Ниже: полоса-лукбук (6–9 лучших образов из `public/lookbook/`, горизонтальный
  скролл), затем «How it works» в 3 шага (Your face → Your occasion → Your looks),
  затем футер с авторками.

### 3.2 Студия `/studio` — стиль «аватар-студия» (референсы: экран с
аватаром и тремя образами в панелях + экран редактора лица с боковыми панелями)
Раскладка на десктопе — три колонки и нижняя панель, всё в тёмном стекле:

```
┌──────────────┬──────────────────────────────┬──────────────┐
│ LEFT PANEL   │        CENTER STAGE           │ RIGHT PANEL  │
│ Profile      │   аватар во весь рост,        │ Look details │
│ (имя, Soul   │   оранжевое свечение сзади,   │ название     │
│  ID статус)  │   тонкий пунктирный контур /  │ note стилиста│
│              │   рамка «сканирования»        │ pieces list  │
│ Occasion     │                               │ palette      │
│ пресеты +    │   после генерации — 3 высокие │ (3–4 кружка  │
│ «Your own»   │   панели-образа рядом,        │  цвета)      │
│ поле         │   клик → образ на сцене       │              │
│              │                               │ [Save look]  │
├──────────────┴──────────────────────────────┴──────────────┤
│ BOTTOM BAR: иконки поводов Date · Wedding · Interview ·    │
│ Party · Weekend   |   [ Style me → ] (оранжевая)            │
└─────────────────────────────────────────────────────────────┘
```
- В правом верхнем углу — оранжевая кнопка «Export» (скачать лукбук / образ).
- Состояния сцены:
  1. **Idle** — базовый портрет-аватар (заранее сгенерированное нейтральное
     фото авторки во весь рост, `public/avatar/base.jpg`), лёгкое «дыхание»
     свечения.
  2. **Styling** — по аватару проходит оранжевая линия-скан сверху вниз,
     текст «Your stylist is putting looks together…», справа 3 пустые панели
     с shimmer.
  3. **Results** — 3 высокие панели 3:4 с образами (как на референсе с
     планшетом), у каждой лейбл «LOOK 01 · CLASSIC», курсивное название и
     1 строка от стилиста. Выбранный образ крупно на сцене, правая панель
     показывает его детали.
- Mobile: колонки складываются — сцена сверху, поводы горизонтальным
  скроллом, панели образов каруселью, курсор выключен.

## 4. Не делаем (non-goals)
- Регистрацию и аккаунты.
- Загрузку селфи посетителями и обучение Soul ID для каждого. Аватар один —
  заранее обученный Soul ID одной из авторок. В левой панели «Profile» это
  показано как готовый профиль (Soul ID: ready ✓).
- Базу данных.
- Примерку вещи по фото, свой шкаф — это «Next steps» в README и питче.
- Ползунки «формы лица» с референса — только как визуальная идея правой
  панели (палитра, детали образа), не как функция.

## 5. Стек

- **Next.js (App Router) + TypeScript**, fullstack: страницы + route handlers.
- **Tailwind CSS**, `framer-motion` для появлений и переходов.
- **Vercel** для деплоя. Без БД.
- Все вызовы Higgsfield **только с сервера** (`app/api/...`). Ключ API никогда
  не попадает в браузер.

## 6. Higgsfield API

Консоль: https://open.higgsfield.ai (API keys, Quick start, Documentation,
Pricing). Баланс pay-as-you-go, подписка не нужна.

⚠️ **Детали ниже собраны исследованием и местами противоречат друг другу в
документации. Перед написанием кода сверь их с Quick start и Documentation в
консоли.** Если расходится — верна консоль.

- Базовый URL: `https://api.higgsfield.ai`, заголовок
  `Authorization: Key KEY_ID:KEY_SECRET`. (`platform.higgsfield.ai` с
  `hf-api-key`/`hf-secret` — вероятно, устаревший API.)
- SDK: TypeScript `@higgsfield/client` (только сервер), Python `higgsfield-client`.
- **Загрузка фото:** `POST /files/generate-upload-url` → PUT файла →
  `public_url`.
- **Soul ID:** `POST /v1/custom-references`
  `{ name, model_version: "v2", input_images: [{ type: "image_url", image_url }] }`.
  ВАЖНО: по умолчанию `v1`, а Soul ID работает только с моделью своей версии —
  всегда передавай `"v2"`. Статус: `GET /v1/custom-references/{id}`
  (`queued` / `in_progress` / `completed` / `failed`), обучение ~10–45 минут.
  5–20 фото лица, разные ракурсы и свет.
- **Генерация:** `POST /higgsfield-ai/soul/v2/standard` —
  `prompt`, `custom_reference_id`, `custom_reference_strength`,
  `aspect_ratio` (3:4), `resolution`, `batch_size`, опц. `style_id`, `seed`,
  `enhance_prompt`. Ответ асинхронный: `request_id` + `status_url` (опрашивать).
  Заголовок `Idempotency-Key` против дублей.
- Статус `nsfw` = заблокировано модерацией, деньги не списываются.
- **Картинки удаляются через ~7 дней** — лучшие сохраняй в `public/lookbook/`
  и `public/avatar/`.
- Лимит ~20 одновременных запросов, при перегрузке 429 с `Retry-After`.
- Цена: страница Pricing или `/estimate/{model}`.

### Получение Soul ID
Скрипт `scripts/create-soul-id.ts` (локально): загружает фото из
`scripts/selfies/` (папка в `.gitignore`!), создаёт reference v2, ждёт
`completed`, печатает ID → `.env.local` как `HF_SOUL_ID`. Тем же Soul ID
сгенерировать базовый портрет для сцены (`public/avatar/base.jpg`):
нейтральная одежда, полный рост, тёмный студийный фон, 3:4.

### Стилист: повод → 3 образа
Без LLM. `lib/occasions.ts`: для каждого пресета — 3 образа с разным
настроением (Classic / Bold / Effortless), у каждого `label`, `title`,
`note` (1 строка стилиста), `pieces` (3–4 вещи), `palette` (3–4 hex) и
`prompt` (англ., для Soul). Структура промпта: вещи (ткань, цвет, крой) +
обувь/аксессуары + место и время + свет + камера. **Тёмный студийный или
вечерний фон в промптах**, чтобы фото органично ложились в тёмный интерфейс.
Пример:
`full-body fashion editorial photo of a young woman wearing a champagne satin slip dress, thin gold jewelry, strappy heels, standing in a dark studio with warm orange rim light, 35mm film look, natural skin texture`
Для «Your own» — общий шаблон с подстановкой текста (+ `enhance_prompt`).
Тексты и промпты — главный носитель «taste», относись к ним как к коду.

## 7. Визуальный язык

Смесь двух референсов: **премиальная тёмная студия** (типографика, сетка,
стекло) + **аватар-студия** (персонаж в центре, оранжевое свечение, боковые
панели, нижний тулбар). Ощущение — личное, дорогое, спокойное.
**Не киберпанк**: никакого неона, многоцветных градиентов и роботов.

### Цвета
```css
--bg:       #0A0A0B;
--surface:  #141416;
--glass:    rgba(255,255,255,0.04);  /* + backdrop-filter: blur(16px) */
--line:     rgba(255,255,255,0.08);
--text:     #F3EFEA;
--muted:    #8C8781;
--accent:   #FF6A2B;
--accent-2: #FFB48A;
```
Оранжевый — только акцент: основные кнопки, 1–2 курсивных слова в заголовке,
свечение за аватаром, активные состояния, линия-скан.

### Шрифты (как в референсе Aesthetic Labs)
- Гротеск: **Inter Tight** (500–600, трекинг −0.03em) для заголовков и UI.
- Курсив: **Instrument Serif Italic** — 1–3 ключевых слова на экран
  («*wearing*», «*every*», названия образов в карточках).
- Лейблы: гротеск 11–12px, uppercase, трекинг +0.08em, `--muted`
  («LOOK 01 · CLASSIC», «SOUL ID · READY»).
- Через `next/font/google`. Интерфейс **на английском** (у Instrument Serif нет
  кириллицы). Если нужен русский — курсив → Cormorant Garamond Italic.

### Компоненты
- Панели и карточки: тёмное стекло, бордер `--line`, скругление 20–24px.
- Кнопки: оранжевая pill (основная), прозрачная с бордером (вторичная),
  иконки-пилюли в нижнем тулбаре (тонкие линейные иконки, активная — оранжевая).
- Аватар на сцене: оранжевое радиальное свечение сзади, тонкий пунктирный
  контур или рамка по краям (отсылка к «сканированию» с референса).

### Курсор (обязательная фишка)
`components/Cursor.tsx`, монтируется в `layout.tsx`:
1. **Точка** 6–8px, `--text`, следует за мышью точно.
2. **Свечение** ~360px:
   `radial-gradient(circle, rgba(255,106,43,0.35), rgba(255,180,138,0.12) 40%, transparent 70%)`,
   `filter: blur(40px)`, `mix-blend-mode: screen`, `pointer-events: none`.
   Плавно догоняет мышь: в `requestAnimationFrame` `pos += (mouse - pos) * 0.12`.
- Только `transform: translate3d`, координаты в `useRef`, без React state.
- Над элементами с `data-cursor="hover"` точка растёт до ~40px и становится
  полупрозрачной обводкой.
- Выключен на `(pointer: coarse)` и при `prefers-reduced-motion`.

### Анимации (сдержанно)
- Появление при скролле: fade + сдвиг 16px, 600ms ease-out.
- Фото проявляются из лёгкого blur; смена образа на сцене — crossfade.
- Скан-линия и shimmer во время генерации.
- Свечение за аватаром медленно «дышит» (scale 1 → 1.05, 4s).
- Никаких прыгающих и вращающихся элементов.

## 8. Защита и расходы
- `.env.local` в `.gitignore`, в репо только `.env.example`. Переменные:
  `HF_API_KEY_ID`, `HF_API_KEY_SECRET`, `HF_SOUL_ID`, `MAX_GENERATIONS_PER_DAY`.
- Лимит генераций на IP в день + общий дневной лимит (в памяти). При
  превышении — **demo-режим**: красивое сообщение и готовые образы из
  `public/lookbook/`, а не ошибка.
- Ошибка или `nsfw` → понятное сообщение и «Try again».
- Используется только лицо авторки с её согласия. Селфи не коммитим.

## 10. Распределение работы

**A — логика и Higgsfield:**
1. Сразу запустить `create-soul-id.ts` (обучение долгое), затем
   сгенерировать `base.jpg`.
2. `lib/higgsfield.ts`, `api/generate`, `api/status`, rate limit, demo-режим.
3. `lib/occasions.ts` — образы, ноты, палитры, промпты (вместе с B).
4. Сгенерировать и отобрать 6–9 лучших образов для лендинга.

**B — интерфейс и подача:**
1. Дизайн-токены, шрифты, `Cursor`, общие компоненты (GlassCard, кнопки).
2. Лендинг.
3. Студия на моках (картинки из `public/`), потом подключить API.
4. Деплой на Vercel, gif, README.

Контракт — типы в `lib/types.ts`, договориться в самом начале.
Если не успеваете — сначала доделать студию до идеала, лендинг упростить до
hero + «Open the studio».
